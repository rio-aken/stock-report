# 複合シグナルチェック（Phase 1）セットアップ

既存の stock-report リポジトリに追加するモジュールです。危険シグナル5条件と強気シグナル（逆パターン）5条件を毎営業日18:30 JSTに判定し、3条件以上成立でメール通知します。

## 判定条件と閾値（src/signals.py 冒頭で変更可能）

| # | 危険シグナル | 強気シグナル（逆） | データ源 | 更新頻度 |
|---|---|---|---|---|
| 1 | 海外投資家が3週連続売り越し | 3週連続買い越し | JPX投資部門別売買状況（市場全体） | 週次（木15:30） |
| 2 | 開示空売り残高が前回比+0.3pt以上 | -0.3pt以上減少 | JPX空売り残高報告（0.5%以上開示分） | 日次（17:00） |
| 3 | 信用買残が前週比+10%以上 | -10%以上減少 | JPX銘柄別信用取引週末残高（PDF） | 週次（火16:30） |
| 4 | 終値が25日移動平均線を下回る | 上回る | yfinance | 日次 |
| 5 | 騰落率-3%以下かつ出来高が20日平均の1.5倍以上 | +3%以上かつ同左 | yfinance | 日次 |

条件1は市場全体の集計値のため、全銘柄共通のフラグとして扱います（JPXは銘柄別の投資部門データを公表していないため）。

## 設置手順

1. このフォルダの中身を既存 stock-report リポジトリのルートにコピー（src/ 内のファイルは既存 src/ に追加。既存の mailer.py をそのまま利用します）
2. `watchlist.csv` を編集し、既存 stocks.py の42銘柄のコードと銘柄名を記入（サンプル2行は差し替え）
3. コミット & プッシュ。Secretsは既存の GMAIL_ADDRESS / GMAIL_APP_PASSWORD / TO_EMAIL をそのまま使用（追加登録不要）
4. Actionsタブ →「複合シグナルチェック」→ Run workflow で手動テスト

## 初回実行後に必ず行う検証（重要）

信用残PDF（銘柄別信用取引週末残高）は列の意味を機械的に確認できないため、**初回実行ログの `numbers` の並びをPDF原本と目視で突合**してください。

1. Actionsのログで `信用買残` 関連の出力を確認
2. https://www.jpx.co.jp/markets/statistics-equities/margin/05.html から同じ週のPDFを開き、監視銘柄の行の「売残」「買残」と `numbers` の並び順を比較
3. 並びが異なる場合は `src/signals.py` の `MARGIN_COLUMN_MAP` の添字を修正

## 動作上の注意（設計仕様）

- **初回〜数週間は「？（判定除外）」が出ます。** 海外投資家フローは3週分、信用買残は前週分のstateが蓄積されてから判定が始まります。これは仕様です。
- 空売り残高は0.5%以上の開示分のみです。開示閾値未満の空売りは反映されません（制度上の限界）。
- `data/signal_state.json` はワークフローが自動コミットして週次データを永続化します。手動で削除すると蓄積がリセットされます。
- JPXサイトの構成変更でデータ取得に失敗した場合、その条件は「？」となり判定から除外されます（誤検知よりデータ欠損の明示を優先する設計）。
- JPX・日証金等のデータは私的利用の範囲で使用してください（再配布不可）。
